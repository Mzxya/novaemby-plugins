# 播放历史 1.0

当前版本 1.0.3。根据官方 SDK 协议 1 重写的 NovaEmby 插件，提供手机优先的观看概况、播放时间线和内容详情。保留插件 ID `playback-history`，旧安装升级后继续读取原 `history.jsonl`。

## 使用

1. 开启 NovaEmby 的播放开始、停止通知，安装并启用插件。16g 起插件功能还需宿主激活。
2. 管理员从「插件 → 播放历史」打开；也可访问 `/history`、`/emby/history` 或 `/mediabrowser/history`。内嵌时可点右上角新窗口入口。
3. 概况按用户和 7/30/90 天查询；播放记录支持关键词、类型、状态、自然日、排序、分页与按内容汇总。
4. 点击内容打开只读详情，读取官方 `host.item`；媒体已删除或暂不可用时显示历史快照。详情可跳到该片名的播放记录。
5. 默认亮色，右上角切换暗色并记住偏好。默认 60 秒更新，支持手动刷新和失败重试。

## 反馈未识别的事件

在插件设置中开启「原始事件诊断日志」（默认关闭），保存后无需重启，对后续收到的订阅事件生效。然后播放、暂停并停止一次视频，在插件日志中复制「原始接收事件」及对应的「原始事件数据」。未识别的事件也会在解析之前输出，包括高频的 playback.progress。

每条事件有 diagnosticId；同一事件的长 JSON 按 part=1/N、2/N 等分段，按序拼接 raw 字段即可还原原文。每段最多 1200 字符；单事件超过 131072 字符时，摘要会标记 truncated=true 并保留原始字节数。日志可能包含用户名、设备和地址，分享前可替换这些值，保留 JSON 键名和结构。收集完成后关闭开关，避免进度日志刷屏。

该开关帮助采集当前无法识别的结构；字段适配需要根据实际原始数据确认，不会仅凭“无法关联”提示猜测字段。

## 海报来源

优先通过官方条目路径查找同目录下的本地封面：媒体名-poster.jpg / png、媒体名.jpg、poster.jpg / png / webp、folder.jpg、cover.jpg。剧集有 SeriesID 时优先读取剧集目录。只读普通 PNG / JPEG / WebP 文件，最大 8 MiB；不接受客户端文件路径，不把宿主文件路径返回页面。

没有本地封面时，可在插件设置的「宿主封面地址」填写**管理员已验证的同源图片路径**，必须包含 `{id}`，禁止外部域名或 Token。浏览器替换媒体 ID 并带同源 Cookie 请求；本地与宿主图片均不可用时，显示带片名和类型的封面占位并提示。

官方插件 SDK 没有图片读取接口，`sdk.Item` 没有图片 URL；不能保证任意宿主版本或媒体都有封面。填入未经验证的地址不能解决权限或接口不存在问题。修复历史媒体信息任务可补回正确的媒体/剧集 ID，但不下载网络海报、不修改媒体文件。

## 已明确的统计边界

- 启用前、停机期间的事件不会补发；不能读取或回填宿主历史数据库。
- 按会话和内容合并开始/暂停/进度/停止；进度不会增加播放次数。部分宿主用 playback.paused 同时上报暂停与恢复，明确的暂停字段优先于事件名称。没有对应会话的进度不新建记录。
- 会话时长是开始到最新确认事件/停止的经过时间，**包含暂停，不是实际观看时长**；不会因为停止事件丢失而无限增长。
- “近期活跃”仅表示最近两分钟收到事件；“状态待确认”不代表离线或在线。未收到停止通知不会自动补造结束事件。
- 停止时缺少开始事件的记录标为不完整，保留已确认进度，不用进度反推观看时长。
- 官方标准字段、旧 `UQVNVII2` 映射和 2026-11-11 实测的 `YINxkXn5Ll` 映射可解析；不认识的结构计入诊断，不再从任意数值推断媒体 ID。
- 同名用户沿用旧版用户名归组规则；账号改名或重名不适用于严格身份审计。
- 时区采用宿主 IANA 时区，空值或无效时区回退 UTC；页面明确显示。自然日筛选兼容夏令时。修改时区后重启插件。

## 数据与任务

数据仍在插件 DataDir 下的 `history.jsonl`。升级不清空、不改 ID；旧日志读入后继续用 put/delete/user 操作追加。只恢复不完整末行，中间损坏报错停止，避免覆盖用户数据。

进度更新在内存合并，后台每五秒检查，累计三十秒后持久化；暂停、结束与正常停机保存最新值。强制结束进程或断电仍可能丢最近未持久化进度。清理先生成并同步新文件，成功替换后才更新内存。

- **清理过期播放记录**：按保留天数、最大记录数，默认每天 04:20；配置变更后的任务执行读取新值。
- **修复历史媒体信息**：默认关闭自动触发；管理员手动执行，重新读取最近 2000 条的名称、剧集和时长，支持任务取消与进度，不修改宿主媒体库。

为延续既有使用方式，页面、查询和管理路由仍为 `auth:none`，适用受信任内网。插件菜单仅管理员可见不等于接口鉴权；页面写操作携带宿主 CSRF，删除和清空需要管理开关及明确确认。清空范围为所选用户全部记录，忽略当前日期和搜索条件。

## 当前能力依据与验证

官方能力依据为根目录唯一的 `novaemby-plugins-main.zip`（提交 `1d07db1e66b3d870c9b9eb97d43c71a66e56a299`）中的 SDK、插件开发教程和 hello 示例。

| 官方能力 | 当前用途 | 边界 |
|---|---|---|
| 播放事件 | 会话合并、进度、暂停/恢复及统计 | 停机事件不补发，不提供实际在线会话列表 |
| host.item | 媒体详情与历史媒体信息修复 | 只读条目信息，不提供海报读取或任意媒体编辑 |
| page / HTTP / CSRF | 内嵌页面、查询与管理 | 不修改宿主 iframe；外层布局由宿主决定 |
| DataDir / tasks | JSONL 数据、清理和修复任务 | 不读取宿主数据库，不补录停机历史 |
| TimeZone | 统一自然日统计与日期显示 | 无效时区回退 UTC |

源码与测试仅保留当前实现，版本说明仅保留 `CHANGELOG/1.0.2.md`。仍维护历史 JSONL 和已确认事件映射兼容，不会因清理丢失升级后的数据读取能力。接口以 http.go 和 manifest.json 为准。

本地执行：

```bash
node plugins/playback-history/web_test.mjs
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tools -p 'test_github*.py'
```

本机不编译、打包或发布。由用户执行 `bash tools/upload-to-github.sh jenley`，个人仓库 CI 负责 Go 检查、竞态测试、双架构编译和 Release 发布，并更新个人索引。本地不保留安装包。

Go 测试和真实浏览器布局、宿主图片接口必须分别在 CI 和部署环境验证；模拟 DOM 测试不能证明海报在实际媒体库已显示。
