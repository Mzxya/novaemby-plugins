# NovaEmby 插件开发教程

> 版本：v1.1（2026-10-20，插件协议 1，对应 NovaEmby 13a）
> 写给所有想给 NovaEmby 写插件的人：照着做就能写出插件、发布到自己的插件仓库，**不需要改 NovaEmby 的代码**。
> 本教程放在公开仓库 [Mzxya/novaemby-plugins](https://github.com/Mzxya/novaemby-plugins) 的 `docs/插件开发教程.md`，以这里的为准。

-----

## 1. 插件是什么

插件是一个独立的小程序。NovaEmby 启动它，通过标准输入输出和它对话。插件崩溃不会影响 NovaEmby，NovaEmby 会自动重启它。

**插件现在能做的事（协议 1）：**

|能力|说明|典型用途|
|--|--|--|
|注册 HTTP 接口|在 NovaEmby 的端口上加接口，例如 `/api/danmu/{id}/raw`，可以要求登录或管理员|弹幕、给第三方工具的扩展接口|
|接收事件|播放开始 / 停止、新片入库、登录、扫描完成等（第 6 节）|入库后推送到别的系统、播放统计|
|配置项|在 manifest 里声明，Web 自动生成设置表单，带说明文字|API Key、开关、数字|
|读取条目信息|按条目 ID 取名称、季集号、TMDB ID、文件路径等|弹幕按剧名和集数匹配|
|写活动记录|写进控制台的活动日志|记录插件做了什么|
|保存数据|每个插件有自己的数据目录，升级后保留|缓存、计数、下载的文件|
|联网|插件程序可以随意访问网络；NovaEmby 设置的代理已经放进环境变量|调用外部 API|

**现在还不能做的事**（要先给 NovaEmby 加能力，见第 13 节）：作为刮削的元数据来源、注册计划任务（13b 计划加入）、修改播放地址、修改 NovaEmby 自己的接口返回的内容、直接读写 NovaEmby 的数据库。

**Emby 原版插件**（.dll）不能运行。想要某个 Emby 插件的功能，就按它的功能写一个 NovaEmby 插件。

## 2. 发布插件的三种方式

|方式|适合|安装时|
|--|--|--|
|**A. 建自己的插件仓库**（推荐）|长期维护、给别人用|别人在 NovaEmby 里添加你的仓库地址，从商店安装、一键更新；要勾选“我了解风险”（不是官方签名）|
|**B. 只打包，上传安装**|只给自己用、试验|管理员上传 zip（第 11 节），要勾选“我了解风险”；没有自动更新|
|**C. 投稿到官方仓库**|希望所有 NovaEmby 用户都能直接装|给 `Mzxya/novaemby-plugins` 提 Pull Request，审核通过后成为官方插件，安装不需要确认|

不需要在自己电脑上装 Go：编译、打包、发布都由 GitHub Actions 完成。

### 2.1 方式 A：建自己的插件仓库（只做一次）

1. 打开 [Mzxya/novaemby-plugins](https://github.com/Mzxya/novaemby-plugins)，点右上角绿色的 **Use this template → Create a new repository**，选你的账号，起个名字（例如 `my-novaemby-plugins`），选 **Public**（NovaEmby 要能匿名下载），创建。
1. 在新仓库里**删掉不属于你的文件**（在网页上点文件 → 右上角 `…` → Delete file，或者克隆到本地删）：
   - `index.json`、`index.json.sig`：这是官方仓库的清单和签名，你的清单会在第一次发布时自动生成。
   - `plugins/hello/`：示例插件。可以先留着当参考，但发布前要删掉或改成你自己的插件（否则你的仓库也会发布一个 hello）。
   - 把 `README.md` 改成你的介绍。
   - `sdk/`、`tools/`、`.github/`、`docs/`、`go.mod` **保留**（开发包、打包工具、发布流程）。
1. 新仓库 **Settings → Actions → General → Workflow permissions** 选 **Read and write permissions**，保存（Actions 要建 Release、提交 `index.json`）。
1. 写好第一个插件（第 3 节）推送后，Actions 会发布它，并在仓库根目录生成 `index.json`。
1. 你的仓库地址是：
   ```
   https://raw.githubusercontent.com/<你的GitHub用户名>/<仓库名>/main/index.json
   ```
   在 NovaEmby 里添加它（`POST /api/v1/admin/plugin/repos {"name":"我的插件","url":"上面的地址"}`，以后 Web 的插件页里也能填），就能在商店里看到你的插件。

**签名**：发布流程里有一步“签名”，需要仓库 Secret `NOVA_PLUGIN_SIGN_KEY`。第三方仓库**不用设置**：NovaEmby 只认官方公钥，你自己签的名同样按“未签名”处理。不设置时日志里有一条“没有设置 NOVA_PLUGIN_SIGN_KEY”的提醒，可以忽略。

**同步官方更新**：开发包、打包工具、发布流程以后可能更新（教程修订记录会写）。需要时把官方仓库的 `sdk/`、`tools/`、`.github/` 复制到你的仓库覆盖即可，不要复制 `index.json` 和 `plugins/`。

国内服务器访问 GitHub 慢时：NovaEmby 的插件设置里填代理（默认跟随刮削设置的代理），或填下载地址前缀 `mirror`（例如 `https://ghproxy.net/`），见第 10 节。

### 2.2 方式 C：投稿到官方仓库

1. Fork `Mzxya/novaemby-plugins`，在 `plugins/<你的插件ID>/` 下写插件（第 3 节），先在自己的 fork 或方式 A 的仓库里测试好。
1. 提交 Pull Request，说明插件做什么、需要哪些配置、会访问哪些网站。PR 上 Actions 只做检查和测试，不发布。
1. 维护者审核代码（会看网络访问、文件读写、有没有收集隐私）。合并后由官方仓库发布并签名。
1. 以后的修改同样通过 PR 提交。

## 3. 写一个新插件（以“弹幕”为例）

以下在你的插件仓库里操作（方式 A 自己的仓库，或方式 C 的 fork）。

1. 复制示例插件：`plugins/hello` → `plugins/danmu`（**目录名必须等于插件 ID**；插件 ID 全球唯一最好，例如加上你的名字 `alice-danmu`，避免和别人的插件重名）。
1. 改 `plugins/danmu/manifest.json`：`id`、`name`、`version`（从 `0.1.0` 开始）、`description`，`entry` 里的文件名改成 `bin/danmu-linux-amd64` / `bin/danmu-linux-arm64`，按需要写 `events`、`routes`、`config`（第 4 节）。
1. 改 `plugins/danmu/main.go`：在 `sdk.Run(&sdk.Plugin{...})` 里填需要的回调（第 7 节）。`Routes` 的键要与 manifest 的 `routes` 一一对应。
1. 推送到 main。Actions 会：`go vet`、`go test`、检查 manifest → 编译 amd64 / arm64 → 打包 → 建 Release `danmu-v0.1.0` → 更新 `index.json`（官方仓库还会签名）。在仓库的 Actions 页面看结果，绿色即成功。
1. NovaEmby 插件商店里点安装（`POST /api/v1/admin/plugin/install {"repoId":"…","id":"danmu"}`；第三方仓库加 `"confirmUnsigned":true`），看插件日志（`GET /api/v1/admin/plugins/danmu/logs`）。
1. 以后修改：改代码，**把 manifest 的 `version` 加一**（例如 0.1.1），推送。版本号没变时 Actions 不会重新发布。NovaEmby 里看到“有更新”，点更新即可（`POST /api/v1/admin/plugins/danmu/update`）。

**想先试试**：
- 只检查能不能编译、manifest 对不对：在分支上改，开 Pull Request，Actions 会跑检查和测试，但不发布。
- 要在服务器上试运行：用预发布版本号（例如 `0.2.0-beta.1`）推送到 main，它会正常发布到商店；测试没问题后改成 `0.2.0` 再推送。预发布版本低于同号的正式版，正式版发布后商店显示的就是正式版。

## 4. manifest.json

放在插件目录根部，打包时原样放进插件包。

|字段|必填|说明|
|--|--|--|
|`id`|是|插件 ID：3–40 个字符，小写字母开头，只能有小写字母、数字和 `-`。发布后不要改（改了就是另一个插件）|
|`name`|是|显示名称，最多 60 字|
|`version`|是|版本号，语义化版本 `主.次.修订`，例如 `1.2.3`；可以带预发布 `1.3.0-beta.1`（低于 `1.3.0`）|
|`protocol`|是|插件协议版本，现在是 `1`|
|`description`|否|说明（显示在商店里），最多 2000 字|
|`author`、`homepage`|否|作者、主页|
|`minServerVersion`|否|需要的最低 NovaEmby 版本，例如 `1.2.0`；开发版 NovaEmby 不检查|
|`entry`|是|每个平台的程序在包里的路径：`{"linux/amd64": "bin/x-linux-amd64", "linux/arm64": "bin/x-linux-arm64"}`。打包工具按这里的路径编译|
|`events`|否|订阅的事件名列表（第 6 节），写错会拒绝安装|
|`routes`|否|HTTP 接口列表（第 5 节），最多 50 个|
|`config`|否|配置项列表（下表），最多 100 个|
|`memoryLimitMb`|否|内存上限 32–4096，默认 256。超过时插件被结束并重启；Go 写的插件会自动按它的 80% 设置 `GOMEMLIMIT`|

插件目录下的 `assets/` 会原样打进包里（图片、模板等），程序里用“可执行文件所在目录/../assets”读取。

### 4.1 配置项

```json
{"key": "apiKey", "type": "secret", "label": "弹弹play App Secret", "description": "在 dandanplay.com 开放平台申请", "required": true}
```

|字段|说明|
|--|--|
|`key`|字母开头，字母、数字、`_`，最长 64|
|`type`|`string` 单行文本、`text` 多行文本、`secret` 密钥（Web 显示为 `********`，不会返回原文）、`int` 整数、`bool` 开关、`select` 下拉|
|`label`|名称（必填，最多 60 字）|
|`description`|说明它能做什么（构思要求每个设置都有说明，请写）|
|`default`|默认值，类型要对（`"你好"`、`3`、`true`）|
|`required`|必填：没填时插件照常启动，但管理员保存配置时会被要求填写|
|`options`|`select` 的选项：`[{"value": "zh", "label": "中文"}]`|
|`min`、`max`|`int` 的范围|
|`maxLength`|字符串最大字数（默认 string / secret 1000、text 20000）|
|`placeholder`|输入框提示|

管理员保存配置时，NovaEmby 先按这些规则校验，再交给插件的 `OnConfigure` 做插件自己的检查；任何一步不通过都不保存，原因显示给管理员。

## 5. HTTP 接口

```json
"routes": [
  {"method": "GET", "path": "/api/danmu/{id}/raw", "auth": "none"},
  {"method": "POST", "path": "/api/danmu/{id}", "auth": "user", "timeoutSec": 60}
]
```

- **路径**：以 `/` 开头，第一段必须是固定文字；参数写 `{名字}`，结尾可以是 `*`（匹配剩余部分，参数名 `*`）。大小写不敏感。
- **自动兼容前缀**：同时响应 `/emby/...`、`/mediabrowser/...`。manifest 里**不要**写 `/emby` 前缀。
- **不能用**：`/api/v1/...`（NovaEmby 自己的 API）、`/health`。和 NovaEmby 已有接口相同的路径以 NovaEmby 为准（插件的不生效）；两个插件声明完全相同的方法 + 路径时，ID 排在前面的插件生效，另一个在日志里有 warn。
- **方法**：GET / POST / PUT / PATCH / DELETE / HEAD；声明了 GET 的接口也响应 HEAD（不返回内容）。
- **auth**：
  - `none`（默认）：不需要登录。带了有效凭据时 `r.User` 仍有值。
  - `user`：需要登录（Emby token 或 API 密钥），否则 401。
  - `admin`：需要管理员，普通用户 403。
- **安全**：转给插件之前，NovaEmby 去掉了 `Authorization`、`Cookie`、`X-Emby-Token`、`X-Emby-Authorization` 等请求头和 `api_key` 等查询参数。插件拿不到用户的 token，用 `r.User` 判断是谁。插件不能设置 `Set-Cookie`。
- **限制**：请求体最大 8 MB，响应最大 32 MB；默认 30 秒超时（`timeoutSec` 最长 300），超时返回 504；插件同时最多处理 16 个请求，再多返回 503。
- **插件没运行**（停用、崩溃重启中）：返回 503 `Plugin unavailable.`；停用后接口不再匹配（404）。

## 6. 事件

在 manifest 的 `events` 里写要订阅的事件。事件内容是 NovaEmby 内部事件结构的 JSON（字段名首字母大写），用 `ev.Decode(&结构体)` 取需要的字段，**只声明用到的字段**即可（以后 NovaEmby 增加字段不影响插件）。可用的事件也可以通过 `GET /api/v1/admin/plugin/events` 查看。

|事件|说明|主要字段|
|--|--|--|
|`auth.login_succeeded`|登录成功|UserID、UserName、DeviceName、Client、RemoteAddr|
|`auth.login_failed`|登录失败|UserName（尝试的用户名）、RemoteAddr、Reason|
|`auth.rate_limited`|某 IP 开始被限速|RemoteAddr、Failures|
|`user.created` / `user.updated` / `user.policy_changed` / `user.password_changed` / `user.deleted`|用户变化|UserID、UserName|
|`library.created` / `library.updated` / `library.deleted`|媒体库变化|LibraryID、Name|
|`library.scan_started` / `library.scan_finished`|扫描|LibraryID、Status、Added、Updated、Removed|
|`metadata.item_ready`|新条目第一次写入元数据（新片入库）|ItemID、LibraryID、Type、Name|
|`metadata.refresh_started` / `metadata.refresh_finished`|刷新元数据||
|`metadata.tmdb_key_invalid` / `metadata.douban_banned`|TMDB Key 无效 / 豆瓣被封控||
|`playback.started` / `playback.paused` / `playback.stopped`|播放|Session（UserName、DeviceName、Client、ItemID、PositionTicks…）、ItemType、ItemName|
|`playback.progress`|进度上报（量很大，处理要快）|同上|
|`playback.denied`|超过同时播放上限|UserName、ItemName|
|`scheduler.task_started` / `scheduler.task_finished`|计划任务|Key、Name、Status|
|`dashboard.memory_high` / `dashboard.memory_normal`|内存过高 / 回落|Percent|
|`license.status_changed`|激活状态变化|From、To|
|`cover.failed`|封面生成失败|LibraryName、Error|

例：

```go
OnEvent: func(h *sdk.Host, ev sdk.Event) {
    if ev.Name == "playback.started" {
        var e struct {
            Session  struct{ UserName, DeviceName string; ItemID int64 }
            ItemName string
        }
        if ev.Decode(&e) == nil {
            h.Info("开始播放", "user", e.Session.UserName, "item", e.ItemName)
        }
    }
},
```

- 事件按发生顺序**一个一个**交给 `OnEvent`；处理慢时后面的事件排队（每个插件最多排 256 个，满了丢弃，插件详情的 `stats.eventsDropped` 会增加）。耗时的事（联网）请自己开 goroutine。
- 插件没在运行时发生的事件不会补发。

## 7. 开发包（Go）

引用：`import "github.com/Mzxya/novaemby-plugins/sdk"`（插件和开发包在同一个仓库，不用另外下载；用模板复制的仓库也保持这个写法，`go.mod` 的 module 名不用改）。

```go
sdk.Run(&sdk.Plugin{
    OnInit:      func(h *sdk.Host) error { … },               // 启动时一次；返回错误 = 启动失败
    OnConfigure: func(h *sdk.Host, cfg sdk.Config) error { … }, // 管理员改配置；返回错误 = 拒绝
    OnEvent:     func(h *sdk.Host, ev sdk.Event) { … },
    Routes: map[string]sdk.HandlerFunc{
        "GET /api/danmu/{id}/raw": func(h *sdk.Host, r *sdk.Request) *sdk.Response { … },
    },
    OnShutdown:  func(h *sdk.Host) { … },                     // 停止前（最多 2 秒）
})
```

**`h *sdk.Host`**（所有方法都能并发调用）：

|方法|说明|
|--|--|
|`h.Config()`|当前配置；`.String("key")`、`.Int("key")`（int64）、`.Bool("key")`|
|`h.Info / Debug / Warn / Error(msg, 键, 值, …)`|写插件日志|
|`h.Item(ctx, "条目ID")`|条目信息 `*sdk.Item`：Type、Name、OriginalTitle、Year、SeriesName、SeasonNumber、EpisodeNumber、Path、ProviderIDs（Tmdb / Imdb / Tvdb / Douban）、RuntimeTicks…；不存在返回 `sdk.ErrNotFound`|
|`h.Activity(ctx, 名称, 说明, "info"/"warn"/"error")`|写活动记录（每分钟最多 30 条）|
|`h.DataDir()`|数据目录（可读写；升级保留；卸载时管理员可以选择保留）|
|`h.Server()`|服务器 ID、名称、版本|
|`h.Proxy()`|NovaEmby 设置的代理；`http.DefaultClient` 已经通过环境变量自动使用它|
|`h.PluginID()`、`h.Version()`、`h.Language()`、`h.TimeZone()`||

**`r *sdk.Request`**：`Method`、`Path`（去掉 /emby 前缀）、`Route`（manifest 里的路径）、`Params["id"]`、`Query.Get("x")`、`Header`、`Body`（[]byte）、`RemoteAddr`、`User`（nil = 没登录；`Name`、`IsAdmin`、`Client`…）、`Context`（客户端断开或超时会取消，联网时传给 `http.NewRequestWithContext`）。

**返回**：`sdk.JSON(200, v)`、`sdk.Text(200, "…")`、`sdk.Bytes(200, "application/xml", b)`、`sdk.Status(204)`；需要响应头时 `resp.Header.Set(…)`。返回 `nil` = 204。处理函数里 panic 不会让插件崩溃（返回 500，写日志）。

**注意**：stdout 是和 NovaEmby 通信的通道，开发包已经把 `os.Stdout` 换成 stderr，`fmt.Println` 的输出会进入插件日志，不会出问题；但不要自己去写文件描述符 1。

## 8. 运行环境

- **系统**：Alpine Linux（NovaEmby 的容器里），程序必须是静态编译的（Go 用 `CGO_ENABLED=0`，打包工具已经这样做）。
- **用户**：NovaEmby 以 root 运行时，插件以 **nobody** 运行：只能写自己的数据目录和 `$TMPDIR`，能读媒体文件（媒体通常对所有人可读）。插件目录的上级目录不允许其他用户进入时，插件改用 NovaEmby 的用户运行（日志有 warn，设置接口 `runAsNobodyNote` 写明原因）。
- **当前目录** = 数据目录；`HOME` = 数据目录；`TMPDIR` = 数据目录下的 `tmp`。
- **环境变量**：只有这些（不会继承 NovaEmby 的环境变量）：`PATH`、`HOME`、`TMPDIR`、`LANG`、`TZ`、`GOMEMLIMIT`、`NOVA_PLUGIN_ID`、`NOVA_PLUGIN_VERSION`、`NOVA_PLUGIN_DATA`、`NOVA_PLUGIN_PROTOCOL`，有代理时还有 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`（大小写两种）。
- **优先级**：nice 10，不和播放、扫描抢 CPU。
- **健康检查**：每分钟 ping 一次，连续 3 次没响应就结束进程并重启（开发包自动回应 ping）。
- **崩溃**：自动重启，等待 1 秒、2 秒、4 秒……最长 1 分钟；10 分钟内崩溃 5 次后停止（状态 `failed`），管理员点“重启”重试。稳定运行 5 分钟后重新从 1 秒开始。

## 9. 版本、升级与兼容

- **发布新版本**：manifest 的 `version` 加一并推送。旧版本仍留在仓库清单里，管理员可以装指定版本（降级）。
- **升级过程**：下载并校验新包 → 解压 → 停止旧版本 → 启动新版本 → 新版本 15 秒内初始化成功才算完成；**失败时自动恢复旧版本**，操作记录写明原因。
- **配置**：升级后保留；新版本删掉的配置项被丢弃，新增的取默认值。
- **数据目录**：升级、重新安装都保留。
- **插件协议**：NovaEmby 以后有不兼容的改动时会升到协议 2，并尽量继续支持协议 1；真的不再支持时，商店会显示“插件使用的协议版本已不再支持，请更新插件”，不会悄悄失效。插件需要更高协议时显示“请先更新 NovaEmby”。
- **加新能力**：NovaEmby 给协议 1 增加新方法（例如 13b 的元数据来源）不需要改已有插件。

## 10. 插件商店与仓库

- **官方仓库**：`https://raw.githubusercontent.com/Mzxya/novaemby-plugins/main/index.json`，NovaEmby 第一次启动时自动添加（删掉后不会再加回来）。
- **签名**：官方仓库清单旁边的 `index.json.sig` 是用官方私钥对清单的签名。NovaEmby 内置官方公钥，验证通过的仓库是“官方签名”（`official: true`），安装时不需要确认。清单里有每个插件包的 sha256，所以签名同时保证了插件包没被改过。
- **第三方仓库**（包括你自己按第 2.1 节建的）：添加后（`POST /api/v1/admin/plugin/repos {"name","url"}`，最多 20 个）同样能浏览、安装、检查更新，只是没有官方签名，安装时要勾选“我了解风险”（`confirmUnsigned: true`）。清单里的 sha256 照样校验，下载过程中被改过的包装不上。
- **代理与加速**：`PUT /api/v1/admin/plugin/settings`：`proxyMode`（`follow` 跟随刮削设置 / `custom` / `none`）、`proxyUrl`、`mirror`（下载地址前缀，例如 `https://ghproxy.net/`，会加在清单、签名、插件包地址前面）。这个代理也会传给插件进程。
- **检查更新**：NovaEmby 每 12 小时获取一次仓库清单（只在有从仓库安装的插件时），插件列表的 `updateAvailable` 为 true 时可以更新；也可以 `GET /api/v1/admin/plugin/catalog?refresh=1` 立即检查。

### 10.1 仓库清单格式（index.json）

由打包工具自动维护，一般不用手改：

```json
{
  "formatVersion": 1,
  "name": "NovaEmby 官方插件",
  "plugins": [{
    "id": "hello", "name": "示例插件", "description": "…", "author": "…", "homepage": "…",
    "versions": [{
      "version": "0.1.0", "protocol": 1, "minServerVersion": "", "platforms": ["linux/amd64", "linux/arm64"],
      "url": "https://github.com/Mzxya/novaemby-plugins/releases/download/hello-v0.1.0/hello-0.1.0.zip",
      "sha256": "…", "size": 3168543, "changelog": "…", "releasedAt": 1792410908
    }]
  }]
}
```

`url` 也可以是相对清单地址的路径（例如 `pkg/hello-0.1.0.zip`）。更新说明：在插件目录下放 `CHANGELOG/<版本>.md`，发布时会写进清单和 Release。

## 11. 调试

|方法|说明|
|--|--|
|插件日志|`GET /api/v1/admin/plugins/<id>/logs`：最近 300 条，含插件的 `h.Info` 等、stderr 输出、NovaEmby 记录的启动 / 退出 / 错误。插件的 `h.Info` 等也会写进 NovaEmby 日志（`module=plugin plugin=<id>`）|
|插件详情|`GET /api/v1/admin/plugins/<id>`：状态、最近的错误、重启次数、内存、事件和请求的统计|
|上传安装|`POST /api/v1/admin/plugin/upload?confirmUnsigned=true`，请求体为插件包 zip。不经过仓库，适合试新版本（同 ID 会覆盖安装，配置和数据保留）|
|操作记录|`GET /api/v1/admin/plugin/operations`：安装 / 升级的结果和失败原因|
|重启|`POST /api/v1/admin/plugins/<id>/restart`|

上传示例（Mac 终端）：

```bash
curl -X POST "http://<服务器IP>:<端口>/api/v1/admin/plugin/upload?confirmUnsigned=true" \
  -H "X-Emby-Token: <API 密钥>" -H "Content-Type: application/zip" --data-binary @danmu-0.1.0.zip
```

插件包在仓库的 Releases 页面下载（标签 `<插件ID>-v<版本>`）。

### 11.1 常见问题

|现象|原因与处理|
|--|--|
|商店里没有新版本|manifest 的 `version` 没改；或 Actions 失败（看 Actions 日志）；或缓存，`catalog?refresh=1`|
|安装时“插件包校验失败”|下载地址前缀返回了错误内容，换一个前缀或改用代理|
|状态 `incompatible`|没有本机平台的程序、`protocol` 不对、`minServerVersion` 高于当前 NovaEmby|
|“插件 15 秒内没有完成初始化”|`OnInit` 太慢（例如联网），把耗时的事放进 goroutine|
|“插件初始化失败：…”|`OnInit` 返回了错误，后面是你返回的原因|
|“无法启动插件程序：…permission denied”|程序没有执行权限（打包工具会设置）；或插件目录对 nobody 不可访问（见第 8 节）|
|“插件内存占用 … 超过上限”|调大 `memoryLimitMb`，或查内存泄漏|
|接口 404|路径与 manifest 不一致；插件已停用；和 NovaEmby 或其他插件的接口冲突（看日志 warn）|
|接口 503|插件没在运行（看状态和日志），或同时请求超过 16 个|
|接口 504|处理超时，加大 `timeoutSec` 或优化|
|配置保存不了|manifest 校验不通过（看返回的 message），或 `OnConfigure` 拒绝|

## 12. 不用 Go 写插件（协议说明）

任何能读写 stdin / stdout 的语言都可以写插件（程序要能在 Alpine 上运行）。每条消息是一行 JSON-RPC 2.0（UTF-8，以 `\n` 结尾）。

**NovaEmby → 插件**

|方法|类型|参数|插件返回|
|--|--|--|--|
|`initialize`|请求|`{protocol, server:{id,name,version,embyVersion}, plugin:{id,version,dataDir}, config:{…}, proxy, language, timeZone}`|`{}`；返回 error 表示启动失败。15 秒内必须回复|
|`configure`|请求|`{config:{…}}`|`{}` 接受；error 拒绝（message 显示给管理员）|
|`event`|通知|`{name, at(Unix 秒), data:{…}}`|—|
|`http`|请求|`{method, path, originalPath, route, params:{}, query:{k:[v]}, headers:{K:[v]}, body(base64), remoteAddr, user:{id,name,isAdmin,isApiKey,deviceId,deviceName,client}或null}`|`{status, headers:{K:[v]}, body(base64)}`，或用 `text:"…"` / `json:{…}` 代替 body|
|`ping`|请求|`{}`|`{}`（10 秒内）|
|`$/cancel`|通知|`{id}`：取消之前的某个请求|—|
|`shutdown`|请求|`{}`|`{}`，然后退出；stdin 关闭时也要退出|

**插件 → NovaEmby**

|方法|类型|参数|返回|
|--|--|--|--|
|`log`|通知|`{level: debug/info/warn/error, msg, fields:{}}`|—|
|`host.item`|请求|`{itemId}`|条目信息；不存在为 error，code 404|
|`host.activity`|请求|`{name, overview, severity}`|`{}`；太频繁为 error，code 429|

请求的 id 由发起方决定（NovaEmby 用整数）；回复时原样带回。stdout 上不是 JSON-RPC 的行会被当作插件日志（warn）。

## 13. 需要新能力时

插件要做的事超出第 1 节的能力时（例如作为刮削的元数据来源、注册计划任务、修改播放地址），需要先给 NovaEmby 加一个能力。请到 [Mzxya/novaemby-plugins](https://github.com/Mzxya/novaemby-plugins/issues) 提 Issue，说明插件要做什么、需要什么能力。能力加入后（增加协议方法，不改协议版本，旧插件不受影响）会更新本教程，之后所有插件都能用。

已计划的能力（13b）：元数据来源（刮削时作为补充来源，只补空字段）、注册计划任务。

## 14. 安全须知

- 插件**不是沙箱**：插件进程能读容器里所有对其他用户可读的文件，能访问网络。只安装自己写的或信任的插件；写插件时只访问插件功能需要的网站和文件，并在说明里写清楚。
- 插件拿不到用户的 token、Cookie；需要以某个用户身份访问 NovaEmby 时，请在插件配置里让管理员填一个 API 密钥（配置项类型用 `secret`）。
- 不要把 API Key、密码写进插件代码或 manifest（仓库是公开的），一律做成配置项。
